# Contributing

This is an open mission. Everyone with intelligence and care to add is welcome.

## How to contribute right now (Day 0)

The codebase is being scaffolded. The most valuable contributions today are:

1. **Read the thesis** — [README](README.md) · [VISION](VISION.md) · [MATHEMATICS](MATHEMATICS.md) · [ROADMAP](ROADMAP.md)
2. **Open an issue** — challenge an equation, propose a missing layer, name a real-world treasury problem we should solve
3. **Share the manifesto** — at [sunheart.ai](https://sunheart.ai) · paste it where serious people read
4. **Propose architecture** — open a discussion or PR with a module design

## The work ahead (Phase 1)

The first concrete build is **the Treasury Visibility Dashboard** — aggregate assets, accounts, inflows, outflows, allocation lanes, idle capital.

See [issue #1](../../issues/1) when it lands.

## Principles for contribution

- **Substance over signaling.** A working module beats a manifesto.
- **Open before clever.** If only you can read it, it doesn't exist.
- **Reversibility before automation.** Reversible-only patterns by default.
- **Anti-extraction by design.** If the design extracts from any participant, it's wrong.
- **Cite the math.** When you propose a routing rule or yield metric, anchor it to one of the eight layers (or propose the ninth).
